# CLAUDE.md: Project context for AI assistants

## What this is

**kafka-connect-servicenow** is OSO's open-source (Apache-2.0) pair of ServiceNow connectors for Apache Kafka Connect, built clean-room on ServiceNow's public REST Table API to replace Confluent's proprietary ServiceNow connectors. Docs: https://servicenowkafkaconnector.com. Maven group `sh.oso`. It mirrors the structure, tooling and release process of `kafka-connect-salesforce-oss`.

| Module | Connector class | Direction |
|---|---|---|
| `connect-servicenow-source` | `sh.oso.servicenow.source.ServiceNowSourceConnector` | ServiceNow to Kafka (backfill plus keyset polling on `sys_updated_on`/`sys_id`) |
| `connect-servicenow-sink` | `sh.oso.servicenow.sink.ServiceNowSinkConnector` | Kafka to ServiceNow (Table API create, patch, put, delete) |
| `snow-core` | Shared ServiceNow protocol library and the fake ServiceNow test harness (`test-jar`) | |
| `e2e-tests` | Docker end-to-end tests against a real Connect worker; generates the configuration reference; checks plugin ZIP contents | |
| `tools/confluent-migration` | `confluent2oss.py` config translator, `verify_cutover.py`, `selftest.py` | |
| `servicenow-event-bridge/` | Placeholder for the optional ServiceNow-side app (PRD-03); not part of any release | |
| `website/` | Docusaurus docs site | |

## Building and testing

```bash
mvn clean verify              # unit + fake-harness + Docker e2e (Kafka + Connect worker)
mvn clean verify -DskipE2E    # without Docker
mvn clean package -DskipTests # plugin ZIPs land in */target/*-kafka-connect-plugin.zip
mvn spotless:apply            # fix formatting (google-java-format, AOSP style)
mvn verify -Pcontract -DskipE2E -DskipUnitTests=true   # real instance; needs SNOW_URL, SNOW_USERNAME, SNOW_PASSWORD
mvn verify -Psoak -DskipE2E -DskipUnitTests=true -pl connect-servicenow-source -am   # 1M-row backfill in 256 MB
```

No ServiceNow instance is needed: `snow-core`'s test-jar ships a fake ServiceNow (WireMock Table API over an in-memory table store, encoded query evaluator, OAuth token endpoint, fault injection). `verify` also runs Spotless (google-java-format needs JDK 21+; the check is skipped on older JDKs and enforced by the JDK 21 CI job), JaCoCo (70% line in `snow-core`, 60% in the connectors) and the Maven Enforcer. CI runs on Java 17 and 21, runs the e2e on Kafka 3.x and 4.x worker images, fails if the generated configuration reference is not committed, and publishes a `migration-evidence` artefact from the Confluent cutover test on every build.

## Releasing

Conventional commits on `main` drive release-please, which maintains the release PR (version bump and CHANGELOG). Merging that PR creates the `vX.Y.Z` tag and GitHub Release; the release workflow validates that every reactor module is at the tag version, builds, deploys signed artefacts to Maven Central, and attaches the two plugin ZIPs with SHA-256 checksums and a CycloneDX SBOM. Never tag by hand. Details: `website/docs/development/releasing.md`.

## Conventions

- Configuration keys are `snow.*`; every property is documented in the generated reference (`website/docs/reference/configuration/*.md`), regenerated by the e2e module. Do not hand-edit those files.
- Shared auth, HTTP, TLS and retry keys are defined once in `snow-core` (`CoreConfigDefs`) and reused by both connectors.
- ServiceNow credentials are Connect `PASSWORD` configs and are never logged; `Redaction` covers `toString`, exceptions and reporter payloads.
- The source never claims deletes and declares exactly-once unsupported; delivery is at-least-once with a documented duplicate bound.
- Retries are bounded inside `snow-core` (`RetryPolicy`, honours `Retry-After`), then surface as `RetriableException` at the task boundary.
- Prefer the fake ServiceNow for new tests; tests that need Docker live in `e2e-tests`; tests that need a real instance are `*ContractIT` and skip without `SNOW_URL`.
- Clean room: only ServiceNow's public documentation and public Confluent documentation are consulted; never inspect proprietary connector code or JARs. Design decisions are recorded in `docs/adr/`.
